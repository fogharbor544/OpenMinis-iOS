# Bot 团队与入口调整

## 当前实现

1. 首页群聊标题使用“群聊”。外观不再展示自动分组，标题生成也不再自动移动旧会话文件夹；已有手动分组数据保留。
2. 首页 Bot 行与会话顶部显示运行状态：回复中、工具执行、等待子任务、等待定时任务、回复完成、错误、已停止可继续或空闲。使用现有运行跟踪器；历史任务不在这里重新加载，缓存释放或重启后无活动的 Bot 显示空闲。
3. Bot 长期记忆管理只从“编辑 Bot”中进入，位于 Model Group 下方。移除了长按菜单、会话菜单、内嵌对话工具栏和旧全局记忆页中的重复 Bot 记忆入口。群聊记忆和共享资料仍独立保留。
4. 会话菜单移除编辑 Bot，增加此 Bot 的定时任务和全局环境变量快捷入口；文件入口改为“打开文件”。首页长按仍可编辑 Bot。点击会话标题只编辑会话标题。
5. 默认创建“指挥官”，身份由稳定 ID 识别，名称可修改。指挥官读取当前 Bot 名称和职责，使用现有 subagent_task 的 bot_id 参数实际分配任务。目标 Bot 的指令、模型组、技能和连接器在独立子会话执行，结果通过现有等待/回调流程交回指挥官。队列、停止、超时和恢复复用现有执行器。群聊中只允许分配给群成员。子任务不自动读取 Bot 私聊历史或长期记忆。
6. 群聊回复改为读取 assistant 文本块；仅在文本块为空时兼容普通 content。思考块和工具载荷不作为回复公开。真实错误和真正无文本结果仍报告错误。
7. 应用设置的 Agent 运行时集中管理 Agent 工具、子代理、环境变量、技能和连接器。编辑 Bot 中的 Agent 运行时区块移除。

## 验证状态

- 已执行：修改后的 Swift 文件与 HEAD 的 Tree-sitter 语法比较（统一换行后无新增错误）、Python AST 检查、git diff --check。
- 已检查测试生成器产物：UI 测试边界和群聊测试临时 Store 的 Swift 语法及临时路径重定向。该检查拦截了编译器调用，**不是 Swift 编译或测试执行**。
- 已补充、尚未执行：群聊 block-only 回复、普通 content 回退、无文字结果及思考/工具过滤回归；指挥官创建幂等、改名保持身份、委派所有权持久化、无效 Bot/群聊拒绝、损坏存储保护。
- 待执行：macOS Swift 行为测试、iOS UI 类型检查、完整 Xcode 构建；真实模型的指挥官拆解/分配/汇总与群聊多成员回复；iPhone 入口、状态、停止/恢复交互。
- 当前 Windows 没有 Swift/Xcode。所有改动仍在本地，尚未提交或推送。

## 真机验收

1. 启动后确认指挥官只出现一次；改名并重启后保持新名称。
2. 创建职责不同的 Bot，向指挥官提出匹配任务，确认出现真实子任务调用、目标 Bot 的工作状态和最终汇总；再测试包含依赖步骤的任务。
3. 验证子任务使用目标 Bot 的模型与能力配置；停用 Agent 工具、删除目标 Bot 或使其模型组不可用时，不得宣称任务已完成。
4. 群聊选全部成员和单个成员，确认文字回复进入群聊且工具/思考内容不混入；停止时不继续下一成员。
5. 首页和会话顶部检查运行/完成/失败状态；返回首页后任务继续更新。
6. 按上述入口清单核对记忆、编辑 Bot、定时任务、环境变量与打开文件。

参考：[dsh-grokbot 项目](https://github.com/nescafe2009/dsh-grokbot) 的团队分配、结果回流与协调者思路。这里以用户明确提出的行为为准，未复制其代码。

状态判断补充：优先读取最新会话的错误和 canResume，再读取 completedAt，避免已停止任务显示为回复完成，或旧会话错误覆盖较新的成功回复。
