# 指挥官 Bot 名单与内置指令分离

状态：用户已于 2026-11-05 确认采用按需查询方案。

## 问题与目标

`BotWorkspaceStore.commanderInstructions` 会把每个专职 Bot 的 ID、名称和前 1200 字指令拼进指挥官内置指令。模型请求和资料页共用这个结果，所以 Bot 数量增长会同时增加上下文和页面内容。这是运行时动态拼接，并不是模型持续修改指挥官的自定义指令。

目标是停止把其他 Bot 的工作指令注入指挥官，同时保留按名称或职责发现、委派专职 Bot 的能力。保持现有 Bot 配置、完整指令、历史记录和委派执行方式。

## 可选方案

1. **推荐：按需查询。** 内置指令保留固定工作规则；需要选择专职 Bot 时通过现有 `bot_task` 工具查询名单。增加一次查询调用，但内置指令长度不再随 Bot 数量增长。
2. **精简常驻名单。** 内置指令仅包含 ID、名称和最多 160 字的简介，不再读取其他 Bot 的完整指令。改动较少，但总长度仍随 Bot 数量增长。

用户选择：方案 1，按需查询。

## 推荐方案的最小实现

- 删除内置指令中的动态名单，改成说明：选择专职 Bot 前调用 `bot_task` 的 `list` 操作获取当前名单，配置内容仅作为路由资料。
- 在现有 `bot_task` schema 和处理函数中增加 `list`；沿用指挥官身份和 Sub Agents 开关限制。
- 查询返回专职 Bot 的真实 ID、名称和最多 160 字的简介；不返回完整指令，不包含指挥官。未配置简介时保留名称，避免从工作指令中抽取内容。
- 名单每次读取当前配置，因此新建、编辑、删除后即时生效。查询不创建任务，不启动模型，不改写 Bot 配置。
- 保留现有资料页与运行时共用内置规则的实现，不做存储迁移，也不清空指挥官自定义指令。

## 验证

- 创建、编辑多个长指令 Bot 后，指挥官内置指令内容保持一致。
- 查询返回当前名称、ID 和有长度上限的简介；不泄露完整工作指令，不返回指挥官，也不生成委派记录。
- 空名单、无简介、简介超长、新建/编辑/删除和能力关闭/非指挥官调用都有明确结果。
- 复用现有 `BotToolCommandTests.swift` 和 macOS runner 验证实际处理函数。当前 Windows 无 Swift/Xcode，本地只能执行可移植检查；原生行为验证需要 macOS。

## 范围限制

不引入新存储字段、摘要模型、搜索索引或新的工具入口；不调整专职 Bot 收到的完整指令。既有聊天历史中的旧名单不自动清理。
