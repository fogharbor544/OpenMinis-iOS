# Bot 多对话与独立长期记忆

本次实现以“设计 Bot 独立长期记忆”会话最后一轮、用户再次贴出的设计为准。角色设定、会话上下文和长期记忆分开保存；不把整段会话摘要当作长期记忆。

## 入口

- 点 Bot 继续上次打开的对话。
- Bot 的菜单提供“新对话”“对话列表”“记忆”；私聊顶部也提供新对话和记忆按钮。
- 新对话有独立上下文，同 Bot 的长期记忆继续可用。旧对话仍可切回。
- “记忆”页面支持查看、搜索、添加、编辑、忘记、来源查看和共享授权。自动保存后，对话底部显示“已记住”和“撤销”。
- 首页“共享资料”用于手动添加共同资料，并选择可访问的 Bot 或群聊。
- 群聊顶部的“记忆”入口管理群内长期背景与约定。

## 数据与归属

SQLite 数据库位于应用 Library/MinisBotMemory/entries.sqlite，不挂载到原来的共享记忆目录。每条记录包含内容、归属、类别、适用范围、来源对话、来源标识、引用原文、创建/更新时间、有效/替换/删除状态、共享授权和防恢复指纹。

私聊按 Bot ID 归属；群聊按群 ID 归属。群聊成员不自动加载各自私聊记忆。用户在条目的“共享”页面勾选目标后，该条目才可被对应 Bot 或群聊检索；撤销授权立即影响后续检索。

会话归属持久保存；Bot 删除后，旧对话不会回退到原来的全局记忆。Bot 的模型、名称或当前会话变更不改变记忆归属。

## 保存、检索与删除

- 显式记忆通过当前聊天引擎的 `memory_write` 保存；用户也可直接在记忆页面添加。
- 自动保存要求引用当前用户原话，并通过稳定偏好/事实与临时要求检查。自动记录保存引用原文，不保存模型推断。工具输出、其他 Bot 发言和程序生成的私聊输入不能作为来源。
- `memory_write` 支持保存、明确纠正和明确忘记。可能冲突的同类别、同范围条目不会被静默覆盖；需要用户明确纠正后用条目 ID 替换。
- 密码、验证码、密钥等明显秘密被拒绝进入普通记忆。记忆页面不能替代密码管理器。
- 每轮和 `memory_get` 都经同一归属过滤。按关键词相关性检索，支持中文双字匹配；最多加载 8 条、4000 字符。用户可固定少量通用偏好，仍受总预算约束。
- 当前用户要求高于旧记忆；记忆作为背景资料，不作为新的指令。
- 忘记会移除当前条目及其旧版本的正文、引用和共享授权。保留内容指纹和来源标识作为防恢复标记，避免旧消息在重载后重新生成记忆。用户可在页面主动重新添加。
- 删除 Bot 会清理该 Bot 所属记忆及其共享授权；删除群聊会清理群聊所属记忆。确认框明确说明，历史会话保留。
- 删除记忆不会抹除已经发送的聊天消息或已经被用户导出的资料。

## 范围与验证

产品按全新安装设计，已移除 `GLOBAL.md`、每日记忆的读写、注入、管理、同步和备份入口。没有 Bot／群聊归属的临时会话不提供长期记忆，不回退到全局记忆。记忆条目当前为本机存储，尚未接入 iCloud 或备份。`SOUL.md` 是仍在使用的角色设定，单独保留角色备份。

针对实际存储和运行时连接代码新增测试，覆盖 A/B 与群聊隔离、主动共享和撤销、重载持久化、纠正与删除、防旧来源恢复、上下文预算、来源校验、秘密拒绝、开关和已删除归属拒绝。多会话测试覆盖新建、恢复、重新选择与历史归属保留。

自动识别是保守的规则与模型工具调用协作，不承诺识别所有自然语言表达。用户可在记忆页面直接管理条目。真机仍应验收聊天顶部入口、会话切换、自动提示与撤销，以及真实模型的显式记忆和纠正行为。
