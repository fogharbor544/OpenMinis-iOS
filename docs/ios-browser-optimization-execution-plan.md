# iOS 浏览器自动化优化执行计划

状态：计划已制定，应用改动尚未开始。日期：2026-11-02。
依据：Mika 对照分析及 Astra（medium）独立审查。原分析文档中的截图消费者和优先级以本计划的修正为准。

## 目标与基线

目标是在保持任务结果正确、工具历史可用和用户接管正常的前提下，减少已识别的重复等待与非必要中间截图。用任务完成耗时、成功率和结果完整性判断收益，不以单次调用提前返回作为成功。

当前目标工作树：`build/worktrees/bot-team-original-avatars`，分支 `codex/bot-team-original-avatars`，制定计划时 HEAD 为 `bbce47b`。它相对审查基线 `56050b2d` 的 BrowserUse、两个 BrowserUseOffload 文件、工具定义和并发工具执行器没有变更；实施前再核对实际基线和工作树状态。

已有其他任务及构建工作记录。本计划不修改或重启它们；本次只保存计划和规划笔记，不启动实施、提交、推送或云构建。

已确认：
- 成功的六类视觉动作统一执行 DOM summary 和隐式截图。正常安静页面的轮询约需 1.5 秒，但不是所有分支的绝对下限，也不是可以无条件删除的耗时。
- DOM summary 内部 JS await 未受其名义 5 秒轮询时限完整约束；项目已有可复用的宿主侧 bounded JS 调用。
- 隐式截图默认不发模型，但有工具卡、持久化历史、CLI image_path 和会话预览消费者。
- 已有 async execute_js、shell minis-browser-use 批处理、scroll_and_collect、标签隔离和并发；不重复建设这些基础能力。
- 尚无本轮真机 A/B 性能数据，不承诺具体加速倍数。

## 阶段顺序

| 阶段 | 交付物 | 进入下一阶段的条件 |
|---|---|---|
| 0 基线 | 固定场景、耗时拆分与原始结果 | 能区分模型、页面、等待、截图、队列/桥接时间 |
| 1 超时和取消 | 有界 DOM 后处理、准确的观察结果 | 正常路径不变；超时/取消不再困住后处理或触发错误重试 |
| 2 显式预览策略 | 默认保留截图，指定流程可省略隐式预览 | 图片消费者契约清楚、默认行为回归通过 |
| 3 采集快速路径 | scroll_and_collect 可显式省略末尾重复后处理 | 条目完整性不降，真机 A/B 显示可重复收益 |
| 4 扩大试点 | 根据实测选择条件等待、读取完善或站点 Skill | 有具体任务和数据证明需要，逐项验证 |
| 后续候选 | 原生 batch、缓存策略等单独实验 | 当前瓶颈确实落在该项，值得付出维护成本 |

每阶段形成独立、可回退的变更单元；实现第一轮仅覆盖 0–3，不将阶段 4 和后续候选自动纳入范围。

## 阶段 0：建立可复现基线

**工作**

1. 复用 `MgrTiming`、`NavTiming`、`SettleTiming`、`PoolTiming`；仅在缺少关联时补充调用标识和必要耗时字段，不另建监控系统。
2. 分开记录 action、DOM summary、snapshot、编码/写入、serial queue、CLI 桥接；另记录任务总时长、模型轮次、失败/重试、输出量。各区间标清包含关系，避免把嵌套时间重复相加。
3. 先使用本地/可控网页固定内容和延迟。保留当前 example.com Bench 作为简单导航检查，增加实际操作场景，不用它代表表单和虚拟列表性能。
4. 同一台 iPhone、相同系统与应用配置、相同测试数据；冷启动/冷缓存和热态分别测量，前台与后台分开记录。
5. 先少量预热并验证 fixture；主场景交替运行 baseline / variant，初始每组至少 30 次。记录中位数、描述性 P95、成功次数和原始样本；不能把这组样本当作生产可靠性证明。波动影响结论时再追加样本。

**场景**

| 场景 | 校验结果 |
|---|---|
| 静态文章导航→读取 | 标题和完整正文与 fixture 一致 |
| 普通输入、受控组件输入、延迟搜索 | 输入正确；晚到结果确实出现，不以值相等代替搜索完成 |
| 虚拟/懒加载列表采集 | ID 集合、条数、顺序及去重符合预期 |
| 两个标签独立操作 | 固定 tab_id，内容与 owner 对应正确 |
| 工具历史与 CLI | 图片路径有效、图像属于正确步骤，无旧图冒充 |
| 接管、取消、secure_input | 原生控制正常，不记录敏感值或错误继续执行 |

优先测不包含模型的确定性浏览器流程，隔离浏览器收益；选定优化通过后，再测同模型的端到端任务，防止模型抖动掩盖变化。日志不记录输入内容、凭据或完整敏感页面数据。

**验收**：基线文件包含提交、设备、配置、样本、失败和阶段耗时；能判断等待和截图各自占比。若实际占比很小，后续只修已证实的超时/取消问题，不为了“提速”扩展架构。

**代码落点**：`src/ios/Debug/BrowserBenchTestView.swift`、`src/ios/Agent/BrowserUse/BrowserUseManager.swift`、现有诊断/CLI 计时入口。只有发现测量缺口才改生产日志。

## 阶段 1：收紧 DOM summary 的超时和取消边界

这是明确的可靠性修复，也可减少异常长尾；不将其宣传为正常页面固定提速。

**工作**

- 在 `collectDomChangeSummary` 使用一个共享截止时间，setup、poll、read 都受剩余预算约束；复用现有 bounded JS 实现，不能每次调用重新获得一整份预算。
- 取消时立即退出后处理，不再使用吞掉取消的 sleep 后继续轮询；按现有工具取消语义向外传播。
- observer 清理只做有时限的最佳努力，清理本身不能重新造成无期限等待。
- 区分“动作已经执行”和“后续观察超时/未完成”。不把已执行点击误报为未执行，避免调用方盲目重放。
- 普通未超时路径保留现有 quiet 阈值和截图行为。本阶段不同时重写导航完成条件。
- 宿主超时不等于已经终止网页脚本；维持现有标签串行、回收和异常恢复规则，不因超时就向卡住的上下文连续追加操作。
- 先只保证 DOM summary 的预算；不把截图和整个 browser_use 声称为同一硬上限。iOS 挂起时不承诺回调按墙钟准时执行，恢复后按截止状态处理。

**验证**

用可控的 JS runner/时钟验证 setup、poll、read 任一不返回、预算耗尽、取消、上下文丢失、正常稳定、持续等速更新等路径。能复用当前测试边界就复用，不为此重构整个 Manager。再用真实 WKWebView 验证回调与标签队列能恢复；使用可控不完成的异步结果，不在用户真实页面注入死循环。

**验收**：前台可执行条件下后处理不无期限挂起；取消后不继续采集/截图；正常路径结果保持一致；观察失败与动作失败可辨。Swift/WKWebView 集成测试通过后才算完成，静态检查不能替代。

**代码落点**：`BrowserUseManager.swift:537` 与现有 `callAsyncJavaScriptBounded`。

## 阶段 2：显式控制隐式预览，保留默认体验

**接口与语义**

建议增加可选 `preview: "default" | "none"`，缺省为 default。名称在实现时与现有参数约定核对，不增加全局用户设置。

- default：沿用当前成功视觉动作的预览生成与历史保存。
- none：只关闭该次隐式预览截图；本阶段仍执行原 DOM summary/等待。参数不得隐式改变完成判定。
- 显式 screenshot 始终生成当次截图；preview 不抑制它。
- secure_input 与用户接管沿用现有专用路径，不通过该选项减少它们需要的观察。
- none 不返回旧 imageFilePath，不把旧 lastScreenshot 当成本次结果；会话预览可保留最近一张，但不能标记为本步新快照。
- 工具记录保留文本结果；明确该步骤省略图片。消费者已有文本 fallback 时复用，不新增伪造图片。
- CLI flag 与 JSON 参数、原生工具 schema 同步支持；旧调用不传参数时兼容。

**消费方核验**

| 消费方 | 必须维持的行为 |
|---|---|
| ConcurrentTools 工具卡/ToolSnapshot | 无图时正常保存文本；有图时保存对应当步图片 |
| ToolLiveSheet 历史展示 | 不显示成另一操作的图；缺图正常阅读结果 |
| BrowserUseOffloadBridge | none 不输出误导的 image_path/minis_url |
| BrowserTabPool 会话预览 | 可以保留旧缩略图，不将它当作新工具证据 |
| 模型与恢复历史 | 不新增隐式图片 tokens，不改变已有显式截图恢复规则 |

**验证与验收**：默认调用输出、截图和历史正常；none 路径无隐式 snapshot/编码/写文件、有正确文本；显式 screenshot、接管、secure_input 仍通过。记录实测节省与快照缺省语义的变化，不声称这是无损删除所有截图。

**代码落点**：`BrowserUseActions.swift`、`BrowserUseManager.swift`、`AIChatViewModel+ToolDefinitions.swift`、`BrowserUseOffload.m`；核对 `ConcurrentTools`、`BrowserUseOffloadBridge`、`ToolLiveSheet` 和 `BrowserTabPool`，只修确实缺少的 fallback。

## 阶段 3：仅对 scroll_and_collect 增加显式采集结果模式

**为什么先做这里**

该动作已经在每轮滚动前安装 observer，等待更新和渲染后采集，最终结果在 Manager 的统一后处理之前已形成。末尾统一等待不会把后到条目补进已形成的结果；其剩余作用是摘要和截图，比通用 click/type 更容易界定边界。

**工作**

1. 先用阶段 0 的测量确认末尾后处理占比。
2. 在该动作上增加明确的返回模式，例如 `result_mode: "standard" | "collected"`；默认 standard，其他动作不能意外启用该特殊模式。
3. collected 仅用于调用方明确只消费本次已采集数据、且 `preview: "none"` 的流程；参数组合冲突时返回清楚的参数错误，不悄悄改变截图契约。
4. collected 返回原采集数据并省略末尾统一 settle/DOM summary/隐式截图，结果说明没有提供最终页面稳定性保证。若要最终视觉状态，随后显式 screenshot；不要将其承诺为跨文档或晚到内容已完成。
5. 保留 scroll_and_collect 内部每轮观察、等待、去重、终止和输出上限；本阶段不调整它们以追求数字。
6. 初期只让选定的可控 CLI 流程使用；验证后再在工具说明中指导模型适用场景，不全局替换默认调用。

**验收**：同样滚动步数及测试数据下，采集 ID/条目集合完整且无重复；standard 行为不变；collected 的摘要/图片缺省符合约定；标签隔离、取消与接管正常。主要验收对象是整个采集任务，不只计一次工具返回。

如果晚到数据导致两种模式都漏采，应单独修内部采集条件；不能用末尾等待存在来证明原结果完整，也不能将漏采归咎于省略后处理而恢复无效等待。

## 第一轮继续/停止条件

- 选定场景的正确性检查全部通过；任何数据遗漏、串标签、错误重放或错误截图均先停止推广，修复后再测。
- 默认体验保持兼容；快速模式的差异由显式参数表达。
- A/B 中等待/截图耗时减少，任务耗时改善超过基线抖动，并在复跑中重现；成功率和重试不恶化。
- 若阶段耗时下降但端到端未改善，只报告局部收益；不扩大宣传。
- 若无可重复收益，保留明确的可靠性修复，停止扩展快速模式与架构。
- 回退以关闭调用方显式选项恢复默认；每阶段独立，避免必须同时撤回其他任务改动。

## 阶段 4：由实测触发的后续工作

| 项目 | 触发证据 | 最小实施范围 |
|---|---|---|
| type/click 条件等待 | 通用 settle 仍占明显比例，且目标条件明确 | 先支持一个具体条件；输入回读与异步业务完成分开，跨文档导航重新识别上下文 |
| get_readable 完善 | 实际出现截断、无效重读、debug 输出占比 | 增加 max_chars、truncated、总长度和分页；动态内容不能混用不同页面版本的 offset |
| 高频站点 Skill | 同站同类任务反复探索入口/生成脚本 | 一两个实际高频站点、只读优先、使用现有 SkillStore，失效回落通用流程 |
| 现有并发的使用说明 | 独立任务仍顺序执行 | 固定 tab_id 的现有跨标签并发，保留单标签顺序与现有上限 |
| 主文档缓存实验 | 重复导航显著占时且响应可缓存 | 普通导航单独试验 useProtocolCachePolicy，保留显式刷新与安全清理 |
| 原生 batch | CLI 桥接或中间处理在实测中明显，现有脚本难表达批次语义 | 复用原动作分发；先定义失败停止、每步结果和批末截图，不引入另一套 JS 引擎 |

质量分类仅针对真实失败样本补充，不用短正文长度直接判定登录墙。fetch 优先复用已有页面会话能力；shell HTTP 不假设自动带有 WebView 登录态。

Mika CDP 网络账本、AX 融合、Android 后台控制、远程浏览器，以及全局提高并发/缩短所有等待，均不在第一轮范围。若以后确有需求，再分别评估。
